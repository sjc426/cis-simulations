Midterm Study Guide — Weeks 1–7

CIS 288 | Exam #1: Cloud Foundations Assessment

The midterm covers everything from Week 1 through Week 7 and comes in two parts. Part 1 is a written exam taken in class — closed book, monitored, multiple choice and short answer. Part 2 is a lab practical: you'll complete a hands-on build in the AWS console and submit documented proof, exactly like a weekly lab but timed. If you did the labs yourself, Part 2 will feel familiar. If you didn't... this is the week that finds out.

📦 Domain 1 — Cloud Foundations (Weeks 1–2)

  • The Three Landlords: AWS, Azure, GCP — market position and console basics
  • Service models: IaaS vs. PaaS vs. SaaS — and which model each service you've used falls under
  • Shared Responsibility Model: what the provider secures vs. what YOU secure
  • Regions, Availability Zones, and why spreading across AZs matters
  • Identity basics: signing in, root vs. admin accounts, why MFA on day one

🖥️ Domain 2 — Compute (Week 3)

  • EC2, Azure VMs, Compute Engine — the same machine from three landlords
  • Instance types and sizing: when do you need more CPU vs. more memory?
  • Pricing models: On-Demand vs. Reserved vs. Spot — and when each makes sense
  • AMIs / images, key pairs, and connecting via SSH
  • Vertical vs. horizontal scaling

🪣 Domain 3 — Storage (Week 4)

  • S3, Blob Storage, Cloud Storage — object storage across the landlords
  • Buckets, objects, and keys; globally unique bucket names
  • Storage classes/tiers: hot vs. cool vs. archive — match the class to the access pattern
  • Object storage vs. block storage (EBS) vs. file storage (EFS) — know which problem each solves
  • Public access blocks and why "accidentally public S3 bucket" is a famous breach genre

🌐 Domain 4 — Networking (Week 5)

  • VPC / VNet — the gated community. CIDR notation: /16 vs. /24 vs. /32 (know the math!)
  • Public vs. private subnets — what makes a subnet "public"? (the route table!)
  • Internet Gateway vs. NAT Gateway — direction of traffic each enables
  • Security Groups: stateful, instance-level, ALLOW-only — vs. NACLs
  • SG references: allowing the web tier to reach the DB tier without IP addresses
  • The 3-tier architecture: web public, app private, database private — always

🔐 Domain 5 — IAM (Week 6)

  • The hotel keycard analogy: root = master key, users = keycards, roles = visitor badges, policies = the rulebook
  • Policy anatomy: Effect + Action + Resource (+ Condition)
  • Evaluation logic: default deny; explicit Deny always wins
  • Groups over direct attachment — why, with the onboarding scenario
  • Roles vs. access keys for services — temporary credentials, no keys in code
  • Least privilege and MFA — the two habits that prevent breaches

⚡ Domain 6 — Serverless (Week 7)

  • The vending machine vs. the leased restaurant — pay-per-execution vs. pay-per-hour
  • Lambda / Azure Functions / Cloud Run functions — handler, runtime, trigger, execution role
  • Stateless design, auto-scaling, and cold starts (which runtimes are slow and why)
  • The 15-minute Lambda timeout — which workloads it disqualifies
  • Common triggers: API Gateway (sync), S3 events (async), EventBridge schedules

📝 Exam Format

  • Part 1 — Written (in class, Wednesday): 30 multiple choice + 4 short answer · 60 minutes · closed book, monitored
  • Part 2 — Lab Practical (take-home, due Sunday 11:59 PM): a timed AWS console build with documented screenshots — VPC, IAM, and S3 tasks combined

How to study: redo Labs 5 and 6 from a blank account without looking at the instructions. If you can rebuild the VPC and the IAM structure from memory, you're ready for Part 2. For Part 1, the six domain cards above are the exam blueprint — every question maps to a bullet on this page.
